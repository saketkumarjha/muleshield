# MuleShield analyst console

An offline-safe analyst console for the MuleShield mule-account investigation
and prevention prototype: a ranked alert queue, provenance-labelled evidence, a
simulated transaction and ring plane, server-enforced maker-checker holds, and a
hash-chained audit trail.

The console recommends. Humans decide. The bank core system executes any action.

---

## Setup

Requires Python 3.11 or newer. No internet access is needed at any point after
`pip install`; there are no CDN scripts, remote fonts, or hosted APIs.

```bash
python -m venv .venv
```

```bash
.venv/Scripts/activate
```

```bash
pip install -r requirements.txt
```

```bash
python -m uvicorn app.main:app --port 8000
```

Then open <http://localhost:8000>.

The demo database is created at `data/console.db` on first start. It is never
cleared automatically — see **Rehearsal reset** below.

### Hosted Vercel demo

Vercel detects `app/main.py` as a FastAPI entry point without a custom routing
file. The deployed function uses its writable temporary directory for SQLite;
the packaged source tree is read-only. This prevents startup failure, but it is
not durable storage: state is isolated to a function instance and may disappear
on a cold start or differ between concurrent instances. The console and health
endpoint label this limitation explicitly.

Use the local console for a stable rehearsal. A genuinely hosted,
multi-instance maker-checker workflow requires an external transactional
database; temporary Vercel SQLite must not be presented as production-grade or
durable persistence.

## Where the numbers come from

**No model-dependent value in this repository is hand-written.** Everything in
`app/fixtures/` is generated by `scripts/build_fixtures.py` from the frozen
champion pack and the API runtime seed owned by the model-truth track:

| Source (in the `boi_x_iith` repository) | Supplies |
|---|---|
| `outputs/api_seed_single_row_ecdf_20260825/` | holdout scores, bands, SHAP reason codes, latency |
| `outputs/ps2_champion_pack_single_row_ecdf_20260825/threshold_registry.csv` | frozen thresholds and train-OOF metrics |
| `MODEL_ACTIVATION_REGISTRY_20260825.json` | active model/threshold version, score semantics, rollback switch |

To regenerate after a model-truth update:

```bash
python scripts/build_fixtures.py --seed-root ../boi_x_iith
```

Each generated fixture carries a `provenance` block recording the SHA-256 of
every source file it was built from. `GET /api/health` returns that block, so a
reviewer can confirm which artifacts the running console was built against.

## Maker-checker

```text
RECOMMENDED -> PENDING_CHECKER -> APPROVED
                               -> REJECTED
            -> EXPIRED
```

Enforced server-side, in `app/api/hold.py`:

- a maker is recorded before any checker action;
- the checker must be a different person from the maker;
- a terminal decision cannot be repeated;
- expiry of the interception window is checked on the server;
- a rejection requires a decision note;
- the state change and its audit entry commit in **one** SQLite transaction, so
  a failed audit write rolls the decision back rather than leaving the two
  disagreeing.

Maker and checker identities are demo-supplied and unverified. SSO,
authentication and RBAC are not integrated, and no core-banking action is
executed.

## Audit chain

`app/services/store.py` keeps an append-only, SHA-256 hash-chained log.
`verify_chain()` recomputes every entry hash from the stored payload and its
predecessor on each request — it is never a constant. A broken chain renders as
a blocking governance error and turns the status strip red. A local hash chain
detects alteration of recorded entries; it is not an external immutable ledger.

## Rehearsing failure states

Simulated-plane outages degrade only their own panel; real model evidence stays
on screen.

```bash
MULESHIELD_SIMULATE_FIXTURE_OUTAGE=graph python -m uvicorn app.main:app --port 8000
```

Accepts `graph`, `timeline`, or `both`.

### Rehearsal reset

Deliberate, never automatic at startup:

```bash
curl -X POST http://localhost:8000/api/demo/reset
```

## What is real and what is simulated

**Real**, from the supplied 9,082-account table: account risk classification,
feature engineering and the leakage audit, risk scoring and banding, and partial
CatBoost TreeSHAP explanation.

**Simulated**, because the supplied table has no transaction edges,
counterparties, timestamps or account identifiers: the transaction plane, graph
and ring detection, FMS/TMS alert ingestion, and NCRP/1930-shaped tickets. Every
one of these carries a persistent `SIMULATED` badge and none of them may be
quoted with precision, recall or detection accuracy.

**Policy or integration contract only**: real-time regulatory feeds,
cross-channel bank data, and prevention of the circulation of fraudulent
proceeds.

**Not implemented**: live core-banking hold execution.

The Governance screen renders all ten official clauses against these four
statuses. There is deliberately no aggregate "10/10 complete" score.

## Claims this console does not make

Production readiness · guaranteed zero false negatives · beating or replacing
MuleHunter.AI · live I4C, NCRP, NPCI or DoT integration · a trained transaction
classifier · autonomous account freezing · production authentication or RBAC ·
fairness certification · temporal generalisation · calibrated probability of
guilt · any active-model latency SLA.

The month field is a complete class-period confound and is excluded, so no
temporal-generalisation claim is valid from this dataset. The holdout carries
only 16 positives: one changed prediction moves recall by 6.25 percentage
points, and cross-validation seed changes move precision by up to 22.3
percentage points.
